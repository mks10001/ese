ese 语言 v2.1 设计评估报告

评估对象：《ese语言规范-v2.1.md》 · 评估日期：2026-09-30 · 性质：v2.0 评估后的复查报告

一、总体结论

一句话结论：v2.1 是一次高完成度的修复——v2.0 的三个严重问题全部解决或基本解决，评分卡总分从 34/70 提升到 48/70。语言已从「艺术原型」进入「可以开工实现」的状态。剩余问题集中在数据结构、词法歧义、运行时错误处理三处，均不阻塞解释器 v0.1 的开发，但需要在 v0.1 开发过程中顺手定案。

建议：按既定路线直接开工 VSCode 插件与 ese check；本报告第三节的 3 个新问题在实现期间解决，不必再等一版规范。

四、v2.1 新引入的优点

  • 加分组件独立作用域设计克制而正确。「组件不捕获外部变量、属性是唯一通道」避免了 JS 闭包陷阱式的隐式依赖，也让组件天然可单测——这个决定比多数新手语言设计者做得好。
  • 加分预留区的文法级强制。预留符号不在 EBNF 中，解析器遇到必须报错。「预留」从文档承诺变成了机器强制，杜绝了「半成品语义被误用」。
  • 加分符号冻结 + 属性扩展给了语言清晰的成长边界：符号集恒定，能力无限。这是从「玩具」走向「可维护」的分水岭。
  • 加分文法要点说明（第五节末尾）把五条设计决策写成了实现者可执行的判据，解释器开发时的争议会大幅减少。

五、遗留与新发现问题

高问题 1：数据结构缺位——没有列表/字典，循环只能数次数

[~ 3次 … ~] 只能重复固定次数；而「取出用户列表并逐个显示」这种最基本的场景无法表达：[# 用户列表 = [] #] 里的 [] 是什么类型？如何取第 i 项？如何遍历？建议 v2.2 定义：

[# 名单 = ["张三", "李四"] #]
[~ 遍历 名单 为 项
  [- {项} -]
~]

数据结构（列表、字典）+ 遍历循环是解释器 v0.2 之前必须补齐的语义，否则组件再多也拼不出动态页面。

高问题 2：三处词法歧义未闭合

文法虽已建立，但以下写法无法唯一解析：

  • 媒体块含星号：[* a * b.png *] —— * 既是定界符又可能出现在文件名里。建议规定文件名不得含 *，或改用 [* a*b.png *] 的最长匹配规则并写进文法。
  • 路径双斜杠：[/ /home /] —— 定界符 [/ 与路径开头的 / 相连成 //。建议路径不写开头斜杠：[/ home /]。
  • 插值范围未定：{名字} 在文法里是 value 的一种，但示例中它出现在 text-body 里。需明确：插值仅允许出现在文字块与字符串内，其他位置视为普通字符。
高问题 3：运行时错误处理未定义

静态错误 ese check 能接住，但运行时问题没有着落：组件调用缺属性怎么办？输入框拿到非预期内容怎么办？[$ a = b / c $] 除以零怎么办？建议三选一并写入 v2.2：① 失败即停（报错含行号，适合教学语境）；② 默认值兜底（缺属性为空串，适合低代码场景）；③ 显式捕获块（新增语法，成本最高）。以 ese 的定位，推荐 ②+① 组合：属性缺省兜底、计算错误即停。

中问题 4：运算符优先级未定义

文法中 calc-expr = value { arith-op value } 意味着严格左结合：1 + 2 * 3 = 9 而非 7。这可以是有意的设计（简单可预期），但必须明文写出并在 ese check 中对混用加减乘除的表达式给提示，否则「算错了」会成为第一批用户的第一批 bug。

中问题 5：内置函数清单未正式化

v1.0 草案里的 打印 在 v2.1 的文法中消失了（既非容器也非语句）。需要一份正式的内置函数表：打印、跳转、长度、转数字……每个给出签名与行为。没有这份清单，解释器无法定义运行时。

中问题 6：组件属性无默认值与校验

[< 欢迎卡 等级=3 > 少传 名字 时目前只能靠运行时报错。建议 属性 名字 = "游客" 支持默认值语法，一行解决，也让组件更接近成熟 UI 库的 props 体验。

低问题 7：异步模型留白

计时器、动画、网络等待未来必然需要异步语义。v2.1 无需实现，但建议在规范里预留一句「异步能力将在 v3.x 以 [~ 等 X秒 ~] 或事件回调形式引入」，防止未来语法破坏现在的括号体系。

六、改进建议（v2.1 → v2.2）

P0在解释器 v0.1 开发期间同步定案三件事
  1. 数据结构 + 遍历循环（问题 1）；
  2. 三处词法歧义的裁决并回写文法（问题 2）；
  3. 运行时错误策略 ②+① 组合（问题 3）。

这三项都是「写解释器时反正要回答的问题」，边实现边定，定完回写规范——不要再单独等一版 v2.2 文档，避免规范与实现脱节。

P1补两份附录

① 内置函数表（问题 5）；② 运算符结合性声明 + ese check 提示规则（问题 4）。均为纯文档工作，各半天以内。

P2组件属性默认值、异步预留声明、Playground

随 v0.2 解释器一起做即可。

七、结论

v2.1 把 ese 从「一份漂亮的想法」变成了「一份可以照着写解释器的合同」。设计层面没有再发现结构性缺陷，剩下的都是实现过程中自然会暴露、也自然会解决的细节。不需要再评估了——开工做工具链，让代码来验收设计。
