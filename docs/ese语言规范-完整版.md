## 一、设计哲学

1. **对称即语法**：每个符号都是一对括号，左右呼应，看见开头就知道结尾——配对错误肉眼可查。
2. **块状思维**：程序是一个个嵌套的「框」，框里放框，层层组装。框即节点，为可视化编辑铺路。
3. **中文友好且双语对等**：默认中文关键字（`[zz]`），英文模式（`[ee]`）完全对等。
4. **前后端同形**：页面布局与后端逻辑用同一套括号风格描述。
5. **换行即结束**：一行一个语句，换行就是句号。不为收尾付税。
6. **符号冻结**：正式符号集恒定为 **17 对**，此后一切能力扩展通过关键字、属性、内置函数与编译目标实现，不新增括号对。

## 二、文件与项目结构

```
我的项目/
  ese.json        ← 构建单元清单（v2.9）：名称、模式、入口、ese-ui 版本
  ese.bd          ← 主程序（入口，固定名）：页面声明、全局状态、全局执行块
  组件库.bd        ← 模块：组件与函数的定义
  样式.fmt        ← 样式资源：容器属性 类= 所引用的类定义
  相加.test.bd     ← 测试文件
```

| 规则 | 内容 |
|------|------|
| 主程序 | 固定命名 `ese.bd`，一个项目有且仅有一个 |
| 模块 | 任意命名，扩展名一律 `.bd`；模块只提供组件与函数，**不得声明页面** |
| 测试 | `xxx.test.bd`，可被 `ese test` 递归发现 |
| 模式 | 一个构建单元内所有 `.bd` 文件必须模式一致（见第十六节） |
| 清单 | `ese.json` 声明构建单元的根与模式；缺失时按「目录内唯一 `ese.bd`」推断（v2.9） |
| 命名空间 | `引入 "./x.bd" 为 x`；不写 `为` 时默认命名空间 = 文件名去扩展名（v2.9，见 11.3） |
| 样式 | `样式.fmt` 提供 `类=` 引用的类；容器亦可用 `样式=` 写字面样式（白名单制，见第九节） |

## 三、符号总表

### 3.1 正式符号（17 对，冻结）

| 符号 | 名称 | 用途 | 层 |
|------|------|------|----|
| `[+ +]` | 浮雕框 | 页面容器，包住一段界面内容；支持属性 | 前端 |
| `[- -]` | 文字块 | 显示一段文字，支持 `{变量}` 插值 | 前端 |
| `[* *]` | 媒体块 | 显示图片或视频 | 前端 |
| `[= =]` | 输入框 | 接收用户输入，绑定变量 | 前端 |
| `[c. .c]` | 按钮 | 纯按钮（配合 `跳转`）；**定界符 `c.` / `.c`，其内侧各须一个空格**（v2.8 起，`c` = click） | 前端 |
| `[> <]` | 行为按钮 | 点击后触发命名逻辑块 | 前端 |
| `[/ /]` | 路由 | 页面路径声明 / 跳转目标 | 前端 |
| `[---]` | 分割线 | 上下内容之间的横线 | 前端 |
| `[> >]` | 执行块 | 定义命名逻辑块 / 立即执行 | 逻辑 |
| `[? ?]` | 分支块 | 条件判断，内含 `[?? ??]` 否则分支 | 逻辑 |
| `[?? ??]` | 否则分支 | 只能出现在 `[? ?]` 的末尾 | 逻辑 |
| `[~ ~]` | 循环块 | 计数循环 / 遍历循环 | 逻辑 |
| `[# #]` | 数据抽屉 | 声明变量（声明位置决定状态层级） | 数据 |
| `[$ $]` | 计算器 | 赋值与算术运算 | 数据 |
| `[< >]` | 组件调用 | 调用已定义组件，可携带子内容 | 复用 |
| `[! !]` | 注释 | 不参与执行，不可嵌套 | 通用 |
| `[!!]` | 行内分隔符 | **可选**，仅一行写多条语句时使用 | 通用 |

> **v2.9 冻结校验**：属性类型标注与 `必须`、派生值 `派生`、遍历键 `键=`、错误边界 `容错` / `兜底`、事件对象 `事件`、样式 `样式` / `类`、可访问性 `替代` / `标签` / `提示`、模块命名空间、文档注释——**全部通过关键字、属性与内置函数实现，未新增任何括号对**。符号表仍为 17 对。

### 3.2 预留符号（语义已占位，当前使用即报错）

| 符号 | 预留含义 | 开放版本 |
|------|----------|----------|
| `[b d]` | 后端块（服务器端逻辑） | v3.0 |
| `[u n]` | 用户块（登录 / 身份 / 权限） | v3.0 |
| `[q p]` | 查询块（数据库查询） | v3.0 |
| `[@ @]` | 网络块（请求外部接口） | v3.x |

> 预留符号**不在文法中**：解析器遇到即报错「该符号将在 v3.x 后开放」。这是机器强制，不依赖文档自觉。

### 3.3 编译指令（pragma，不占符号表名额）

`[ee]` / `[zz]`：模式声明。约束见第十六节。

## 四、基础语法规则

### 4.1 一切皆嵌套

```
[+
  [- 外层文字 -]
  [+
    [- 内层文字 -]
  +]
+]
```

### 4.2 换行即结束

- 一行写一个语句，换行即该语句结束，**不需要任何收尾符号**。
- 容器靠右括号闭合，与换行无关。
- `[!!]` 仅作为可选行内分隔符：一行内写多条语句时才用。

```
[- 你好 -]
[- 欢迎回来 -]

[- 你好 -] [!!] [- 欢迎回来 -]      [! 行内分隔符用法 !]
```

### 4.3 注释

```
[! 这是注释，不参与执行 !]
```

注释必须成对闭合，**不可嵌套**。

### 4.4 分割线

```
[---]
```

### 4.5 缩进

缩进仅用于人类可读性，**不参与语义**。语义由括号配对 + 换行决定。

## 五、作用域规则

### 5.1 词法块级作用域

- `[# 变量 = 值 #]` 的作用域为**包含它的最内层容器**（从声明处到容器闭合）。
- 内层块可**读取**外层变量（逐层向外查找）。
- 内层赋值修改**最近的外层声明**；要新开同名变量必须先用 `[#]` 声明。

```
[# 计数 = 0 #]
[+
  [$ 计数 = 计数 + 1 $]      [! 修改外层 计数 !]
  [~
    [# 计数 = 99 #]          [! 新开局部 计数 !]
    [$ 计数 = 计数 + 1 $]
  ~]
+]
```

### 5.2 组件作用域

组件是**独立作用域**：只访问自己声明的状态与传入的属性，**不捕获外部变量**；与外界唯一通道是属性传值。

### 5.3 页面作用域

`[/ 页面 … /]` 体内声明的变量属于该页面，页面内的组件仅在收到属性时可见其值。

## 六、数据结构

### 6.1 字面量

```
[# 名单 = ["张三", "李四", "王五"] #]
[# 用户 = { "名字" : "张三", "等级" : 3 } #]
```

- 列表：`[ 元素, 元素, … ]`
- 字典：`{ "键" : 值, … }`（键必须为引号字符串）
- **两者均只允许出现在值位置**（`[$ $]` 右侧、属性值、条件、字面量嵌套内）。

### 6.2 访问与操作

```
[$ 名字 = 用户.名字 $]            [! 点语法取字典值 !]
[$ 第一 = 取第(名单, 1) $]        [! 列表取项，序号从 1 起；越界即停 !]
[$ 个数 = 长度(名单) $]
[$ 加入(名单, "赵六") $]
```

**安全取值（v2.9 起）**：默认严格，安全取值是**显式选择**。

```
[$ 名字 = 取(用户, "名字", "游客") $]      [! 键不存在 → 返回 "游客"，不终止 !]
[$ 第一 = 取或(名单, 1, "") $]             [! 越界 → 返回 ""，不终止 !]
```

**点语法必须紧贴**（v2.8 起）：`.` 两侧不得出现空白。

```
[$ 名字 = 用户.名字 $]            [! 合法 !]
[$ 名字 = 用户 . 名字 $]          [! 非法：点号旁有空白 !]
[$ 名字 = 用户 .名字 $]           [! 非法 !]
```

这条限制的存在理由是**为按钮定界腾出词法空间**：按钮写作 `[c. 文字 .c]`，靠「点号旁的空白」与点语法 `c.a.c` 区分（见 7.5）。若允许散写点语法，两者会在 `[c. a .c]` 这一形态上重新撞车。代价是值位置不能写「松散的点语法」，收益是词法层面零歧义、解析器零回溯。

### 6.3 遍历

```
[~ 遍历 名单 为 项
  [- {项} -]
~]

[~ 遍历 用户 为 项
  [- {项.键} = {项.值} -]
~]

[~ 遍历 购物车 为 项 键={项.id}      [! v2.9：重渲染身份 !]
  [- {项.名字} -]
  [= 数量 =]
~]
```

遍历中修改被遍历集合为未定义行为，ese check 给出警告。

**遍历键（v2.9 起）**：`键=`（key）只能是值位置表达式，同一循环内必须唯一。

- 有键时重渲染**按身份复用节点**：输入框焦点、动画状态、滚动位置得以保持。
- 无键时行为同 v2.8（按序号重渲染）；ese check 检测到「循环内含输入框或组件却无键」时警告「可能丢失输入焦点」。

## 七、运算符、表达式与内置函数

### 7.1 优先级与结合性（高 → 低）

| 优先级 | 运算符 | 英文写法 | 结合性 |
|--------|--------|----------|--------|
| 1 | `( )` | — | — |
| 2 | 函数调用 `f( )` | — | 左 |
| 3 | `非` | `not` | 右 |
| 4 | 一元 `-` | — | 右 |
| 5 | `*` `/` | — | 左 |
| 6 | `+` `-` | — | 左 |
| 7 | `==` `!=` `>` `<` `>=` `<=` | — | 左 |
| 8 | `并且` | `and` | 左 |
| 9 | `或者` | `or` | 左 |

```
[$ 结果 = 1 + 2 * 3 $]                  [! 7 !]
[? 非 已登录 或者 计数 > 10
  [- 请先登录 -]
?]
```

### 7.2 类型规则

- 不做隐式转换。`+` 两端必须同为数值或同为字符串（字符串相加为拼接），否则运行时错误即停。
- 比较两端必须同类型；`==` 对列表/字典做深度相等比较。
- 转换函数：`转数字(x)` / `转文字(x)`。
- 布尔值：`是` / `否`。

### 7.3 内置函数表

| 中文 | 英文 | 签名 | 说明 |
|------|------|------|------|
| 打印 | print | 打印(x) | 输出到控制台 / 构建日志 |
| 跳转 | goto | 跳转(路径) | 页面跳转 |
| 取第 | take | 取第(列表, 序号) | 第 n 项，从 1 起，越界即停 |
| 取 | get | 取(字典, 键, 缺省) | 键不存在返回缺省，不终止（v2.9） |
| 取或 | getOr | 取或(列表, 序号, 缺省) | 越界返回缺省，不终止（v2.9） |
| 长度 | len | 长度(列表或字典) | 元素个数 |
| 加入 | push | 加入(列表, 值) | 尾部追加 |
| 包含 | contains | 包含(列表或字典, 值) | 是否包含，返回 是/否 |
| 键列表 | keys | 键列表(字典) | 全部键的列表 |
| 转数字 | toNumber | 转数字(x) | 失败即停 |
| 转文字 | toText | 转文字(x) | 任意值转文字 |
| 断言 | assert | 断言(名称, 表达式) | 测试断言 |
| 渲染 | render | 渲染 内容 | 插槽输出（语句形式） |

### 7.4 插值

`{变量}` 仅在**文字块与字符串内**解析为插值；值位置的 `{ }` 是字典字面量；其他位置为普通字符。插值内可写点语法：`{用户.名字}`。

### 7.5 按钮定界符与括号歧义（v2.8 修订）

**按钮写作 `[c. 文字 .c]`**（`c` = click，两端点号形如按钮边框）。**`c.` 之后与 `.c` 之前必须各有一个空格**——这两个空格是定界符的组成部分，不是排版习惯。

```
[c. 去首页 .c]
[c. 提交 (v2) .c]        [! 按钮文字可含单层半角括号 !]
[c. 用户.名字 .c]        [! 按钮文字内可含紧贴的点语法 !]
[c. .c]                  [! 空按钮：单个空格同时充当前后空格 !]
```

| 形态 | 唯一解读 |
|------|----------|
| `[c. 文字 .c]`（点号内侧有空格） | **按钮** |
| `[c.a.c]`（点号两侧紧贴） | **列表**（单元素，元素为点语法 `c.a.c`）——不可能是按钮 |
| `[( 表达式 )]` | **单元素列表**（元素为括号表达式）——不可能是按钮 |
| `( 表达式 )` | 括号表达式（提高优先级） |

**收益**：

1. **词法上唯一**：按钮定界符为「字母 `c` + 点号 + **空白**」，与列表 `[...]`、括号表达式 `(...)`、点语法 `a.b` 三者均不同源。
2. **v2.7 的残留同形被彻底消灭**：`[c.a.c]`（紧贴）从此只能是列表，想写按钮就必须写成 `[c. a .c]`。**按钮与列表之间不再存在任何同形构造**，位置裁决（语句位置 = 按钮容器、值位置 = 列表）从「消歧必需」降级为「诊断提示」。
3. **按钮文字可含单层半角括号**：终止序列是 ` .c]`（空格 + 点号 + `c` + `]`），`(v2)` 里的单个 `)` 不触发闭合。
4. **视觉辨识高**：两侧点号像按钮边框，且内侧留白符合中文排版习惯，与列表、括号表达式一眼可辨。
5. **与既有字母系符号同族**：`[ee]`/`[zz]`（模式 pragma）与预留区 `[b d] [u n] [w m] [q p]` 同属字母标记，风格自洽。

**配套硬规矩**：

6. **点语法必须紧贴**（v2.8 新增）：`.` 两侧不得有空白，即 `用户.名字` 合法、`用户 . 名字` 非法（见 6.2）。这是第 2 条成立的前提——若允许散写点语法，`[c. a .c]` 又会被两种解读抢占。
7. 按钮文字内不得出现 `]` 与 ` .c]` 序列；需要时用全角 `］`。空按钮写作 `[c. .c]`（单空格兼作前后空格），`[c.  .c]`（多空格）等价。
8. **模式无关**：`c` 是跨中英模式通用的定界字母（不做 `[ee]`/`[zz]` 切换）。
9. **ese check 专项诊断**（三条）：
   - 语句位置出现 `[( … )]` 或 `[(( … ))]`（v2.5 / v2.6 旧写法）→「按钮需写作 `[c. 文字 .c]`（点号内侧各需一个空格）」；
   - 语句位置出现**紧贴**形态 `[c.文字.c]` →「按列表解析，不是按钮；若想写按钮请在 `c.` 之后与 `.c` 之前各加一个空格」；
   - 值位置出现带空格的 `[c. … .c]` →「按钮不能出现在值位置，请移到语句位置」。

```
[+ 居中
  [c. 去首页 .c]                    [! 语句位置 → 按钮 !]
  [c. 提交 (v2) .c]                 [! 按钮文字含单层半角括号 !]
  [# 路径 = [c.a.c] #]              [! 值位置 → 列表，元素为点语法 c.a.c !]
  [# 名单 = [(1 + 2), 4] #]         [! 值位置 → 列表，首元素为括号表达式 !]
  [$ 结果 = (1 + 2) * 3 $]          [! 值位置 → 括号表达式 !]
+]
```

## 八、错误处理与诊断规范

### 8.1 两级策略

| 级别 | 场景 | 行为 |
|------|------|------|
| 宽容级 | 组件调用缺少**非必须**属性 | 有默认值用默认值，否则取空串（数值语境取 0）；ese check 给**警告** |
| 严格级 | 除以零、类型不匹配、`取第` 越界、键不存在、缺少**必须**属性、调用未定义函数/组件、跳转到未声明路径 | **立即终止**并报错，含错误码、文件名、行号、列号与原因 |

```
错误：ese.bd 第 12 行 —— 除以零（[$ 一半 = 总数 / 0 $]）
```

### 8.2 设计理由

低代码用户需要「页面先能出来」（宽容），但算错了必须立刻看见（严格）；不引入捕获语法，保护语言简洁度。

### 8.3 错误码与诊断规范（v2.9）

| 段 | 范围 | 示例 |
|----|------|------|
| `ESE1xxx` | 词法与语法：括号配对、预留符号、按钮定界、模式冲突 | ESE1001 括号未闭合 |
| `ESE2xxx` | 静态检查：类型、作用域、属性拼写、派生循环 | ESE2003 未知属性 |
| `ESE3xxx` | 运行时：除零、越界、类型不匹配 | ESE3001 除以零 |
| `ESE4xxx` | 构建与工具：清单不一致、模式冲突、迁移失败 | ESE4001 模式冲突 |

诊断对象（解析器、ese check、编辑器插件、`ese build` 四方统一结构）：

```json
{ "code": "ESE3001", "severity": "error", "file": "ese.bd", "line": 12,
  "column": 5, "message": "除以零", "hint": "检查除数，或使用 容错 降级显示" }
```

文本格式：

```
错误 ESE3001 ese.bd:12:5 除以零（[$ 一半 = 总数 / 0 $]）
提示 检查除数，或使用 容错 降级显示
```

- 报错语言**跟随文件模式**（`[zz]` 中文 / `[ee]` 英文），不由用户配置。
- 消息模板由 `diagnostics.json` **单一数据源**生成，**禁止手写第二份**。

### 8.4 错误边界：`容错` 容器（v2.9）

```
[+ 容错 兜底="数据加载失败"
  [- 总价：{单价 * 数量} -]
+]

[< 图表 数据=报表 容错=是 兜底="图表暂不可用" >]
```

1. `容错`（tolerant）是**开关属性**，可出现在任意容器与组件调用上；`兜底`（fallback）指定降级显示的文字。
2. 其内部发生的**严格级错误被捕获**：该容器整体渲染为 `兜底` 文字（未给 `兜底` 时为空）。
3. 错误**不静默**：仍写入控制台与 `ese serve` 日志，并带完整错误码。
4. 未使用 `容错` 时行为完全不变——**立即终止**。
5. **错误不穿透组件边界**：组件内部错误由组件自身的 `容错` 负责，调用方不接管。

**设计理由**：低代码场景下「一个字段缺失导致整页白屏」的代价过高；`容错` 把降级范围交给用户**显式声明**，粒度可细到单个组件，且**不引入 try/catch 语法**，符号表不受影响。

## 九、前端层符号详解

```
[+ 宽=600 居中 背景="#f7f8fa" 类="卡片主"   [! 浮雕框：属性驱动排版（取代 v2.0 的 [w m]） !]
  [- 欢迎来到我的网站 -]
  [---]
  [* 头像.png 替代="站长的头像" *]            [! 媒体块：文件名禁含 * 与空白；替代=v2.9 !]
  [= 名字 标签="用户名" 提示="请输入姓名" =]   [! 输入框：可访问性属性 v2.9 !]
  [c. 去关于 .c] 跳转 about                   [! 纯按钮 + 跳转（c. / .c 定界，内侧各需空格） !]
  [> 提交 <] 调用 提交                        [! 行为按钮：绑定命名逻辑块 !]
+]

[+ 样式="圆角:12; 字号:15; 色:#333333"      [! 字面样式：白名单 12 项 !]
  [- 正文 -]
+]
```

| 要点 | 规则 |
|------|------|
| 媒体文件名 | 不得含 `*`；**v2.9 起亦不得含空白**（文件名 = 首个空白前的片段）。需带空格的文件名用引号形式 `[* "我的 图.png" *]` |
| 媒体可访问性 | `替代="描述"` 编译为 `alt`；缺失时 ese check 给**警告**（v2.9） |
| 输入框可访问性 | `标签="…"` 编译为 `<label>` 并关联；`提示="…"` 编译为 `placeholder`（v2.9） |
| 常用属性 | `宽=数字`、`居中`、`背景="色值"`、`间距=数字` |
| 样式逃生舱 | `类="名字"` 引用 `样式.fmt` 中定义的类或 ese-ui 内置类；`样式="…"` 写字面样式（v2.9） |
| 样式白名单 | **12 项**：色、背景、边框、圆角、字号、字重、行高、间距、内距、外距、对齐、宽度；白名单外报错 `ESE2010` |
| 样式优先级 | `样式` > `类` > 内置默认 |
| 路径 | 不得以 `/` 开头（消除 `//` 歧义），URL 前导斜杠由编译器补全 |

## 十、逻辑层与事件

```
[! 定义命名逻辑块 !]
[> 提交 :
  [? 名字 == "" 或者 长度(名字) > 20
    [- 名字不合法 -]
    [??
      [< 欢迎卡 名字=名字 >]
    ??]
  ?]
>]

[! 绑定：行为按钮 + 调用 !]
[> 提交 <] 调用 提交

[! 无名执行块：立即执行 !]
[>
  打印("页面已加载")
>]
```

**事件传参与事件对象（v2.9）**

```
[> 加购(编号) :                       [! 命名逻辑块可声明形参 !]
  [$ 购物车 = 加入(购物车, 编号) $]
>]

[~ 遍历 商品 为 项 键={项.id}
  [- {项.名字} -]
  [> 加购 <] 调用 加购({项.id})        [! 绑定处传参 !]
~]

[> 记录 :
  打印(事件.目标)                     [! 事件对象：仅在执行块内可用 !]
>]
```

| 事件字段 | 含义 |
|----------|------|
| `事件.值` | 触发元素的值（输入框内容） |
| `事件.索引` | 列表项序号（从 1 起） |
| `事件.项` | 列表项本身 |
| `事件.目标` | 触发组件 / 元素的名字 |

- `[> 名字 : … >]` 定义命名逻辑块（**命名触发器**方案，是按钮与逻辑的唯一绑定方式）。
- 逻辑块可声明形参；绑定处用 `调用 名字(实参, …)` 传值；无参仍写作 `调用 名字`。
- 参数**按值传递**；实参与形参数量不符为错误（`ESE2009`），形参重名为错误。
- `[> <]` 按钮通过 `调用` 绑定；无名执行块在到达时立即执行。
- `[?? ??]` 只能出现在 `[? ?]` 尾部。

## 十一、组件与 ese-ui 标准库

### 11.1 组件定义与调用

```
[+ 组件 欢迎卡
  属性 名字 文字 = "游客"                  [! v2.9：类型标注 + 默认值 !]
  属性 等级 数字 = 1
  属性 页数 数字 必须                      [! v2.9：必须（调用处缺即报错） !]
  [+ 居中
    [- 你好，{名字}！等级 {等级} -]
  +]
+]

[< 欢迎卡 名字="张三" 等级=3 页数=1 >]
[< 欢迎卡 页数=1 >]                        [! 其余走默认值 !]
```

**属性契约（v2.9）**

| 要素 | 写法 | 行为 |
|------|------|------|
| 类型标注 | `属性 名字 文字` | 类型：文字 / 数字 / 是否 / 名单 / 字典 / 任意（`text` / `number` / `bool` / `list` / `dict` / `any`）；**未标注 = 任意**（保持 v2.2 兼容） |
| 默认值 | `属性 等级 数字 = 1` | 调用处未传时使用该值 |
| 必须 | `属性 页数 数字 必须` | 调用处未传即**运行时报错**（`required`） |

调用处静态校验（ese check）：

| 情形 | 级别 |
|------|------|
| 缺少 `必须` 属性 | 错误 |
| 传值类型与标注不符 | 错误 |
| 传入组件未声明的属性名 | 警告（拼写保护，`ESE2003`） |
| 缺少非必须属性 | 警告（宽容兜底生效） |

原则：**默认仍宽容，`必须` 是按属性逐项打开的收紧开关**——不提供全局严格模式，避免一刀切吓退低代码用户。

### 11.2 插槽（子内容）

```
[+ 组件 卡片框
  属性 标题 = ""
  [+ 边框
    [? 标题 != ""
      [- {标题} -]
    ?]
    渲染 内容                              [! 输出调用处的子内容 !]
  +]
+]

[< 卡片框 标题="公告"
  [- 这是卡片正文 -]
>]
```

### 11.3 模块引用

```
引入 "./组件库.bd" 的 欢迎卡, 页脚        [! 直接引入具体名字 !]
引入 "./ui.bd" 为 ui                      [! v2.9：绑定命名空间 !]
引入 "./工具.bd" 为 工具

[< ui.卡片 标题="公告" > [- 正文 -] >]
[$ 结果 = 工具.格式化(名字) $]            [! 函数的命名空间引用 !]
```

- 被引入文件中的组件即可调用；**跨模式引入被拒绝**（见第十六节）。
- `引入 … 为 名字` 绑定命名空间（`as`）；**不写 `为` 时默认命名空间 = 文件名去扩展名**。
- 引用名为 `命名空间.成员名`。点号**仅在被引用位置解析**，与值位置点语法（见 6.2）不冲突。
- 命名空间解决模块间同名组件的冲突，是 `ese-ui` 与第三方组件库共存的前提。

### 11.4 ese-ui 标准库第一批（内置，无需引入）

| 组件 | 用法 | 说明 |
|------|------|------|
| `卡片` | `[< 卡片 标题="…" > 子内容 >]` | 带标题的卡片容器 |
| `列表` | `[< 列表 数据=名单 > [- {项} -] >]` | 遍历渲染，子内容中可用 `{项}` 与 `{序号}` |
| `导航栏` | `[< 导航栏 项目=… >]` | 顶部导航；属性接口待去嵌套字面量化（v2.3 评估遗留） |

### 11.5 文档注释与 `ese doc`（v2.9）

```
[! 文档 : 带标题的卡片容器，正文由调用处提供。属性 标题 为卡片抬头文字。 !]
[+ 组件 卡片主
  属性 标题 文字 = ""
  ...
+]
```

- 以 `文档`（doc）开头的注释为**文档注释**，绑定其后紧邻的定义（组件、函数）。
- `ese doc` 扫描全部文档注释与属性契约，生成 Markdown / HTML 版 API 文档。
- **不新增括号对**——复用 `[! !]` 注释符号。

## 十三、状态管理

### 13.1 三级状态

| 声明位置 | 层级 | 生命周期 | 可见范围 |
|----------|------|----------|----------|
| `ese.bd` 顶层（页面外） | 全局状态 | 整个运行期 | 全部页面与组件（只读） |
| 页面体内 | 页面状态 | 页面打开期间 | 该页面及其组件 |
| 组件体内 | 组件状态 | 组件存活期间 | 仅该组件 |

### 13.2 响应式与数据流

- 任何状态被赋值（`[$ x = … $]`）时，**所有引用它的界面自动更新**，无需手动刷新。
- **单向数据流**：属性向下传，事件向上抛。
- 全局状态仅允许在**全局执行块**中修改；跨层直接赋值被 ese check 拒绝。

```
[> 全局 :
  [$ 访问语 = "欢迎回来！" $]
>]
```

### 13.3 SSR 下的状态

全局状态每请求独立初始化；页面状态服务端渲染初值；组件状态仅存在于客户端水合之后。

### 13.4 派生值（v2.9）

```
[# 单价 = 12 #]
[# 数量 = 3 #]
[$ 派生 总价 = 单价 * 数量 $]        [! 只读、随依赖自动重算 !]
```

1. 派生值**只读**——对其赋值是错误（`ESE2007`）。
2. **依赖自动追踪**：任一所依赖状态被赋值时自动重算，界面同步更新；无需手写同步语句。
3. 派生值**不引入新的状态层级**，仍属于声明所在层（全局 / 页面 / 组件）。
4. 允许链式派生；**循环依赖**在 ese check 阶段报错（`ESE2008`）。

## 十五、编译模型（ese build / ese serve）

**SSR 是编译目标，不是语言特性——不引入任何新语法。**

| 命令 | 模式 | 行为 |
|------|------|------|
| `ese build` | 静态生成（默认） | 页面预渲染为独立 HTML + 小体积交互 JS；纯展示页零 JS |
| `ese serve` | 服务端渲染 | 页面按请求实时渲染；交互部分水合后客户端接管 |

规则：

1. 声明式部分（浮雕框 / 文字 / 媒体 / 组件）在服务端渲染为完整 HTML——首屏无白屏。
2. 执行块、输入绑定、组件状态编译为按页拆分的 JS，仅含交互的页面加载。
3. 纯静态产物可部署至任意静态托管。

## 十六、双语模式与互不互通

### 16.1 模式声明

- `[zz]`：中文模式（**默认**，可省略）。
- `[ee]`：英文模式。
- 括号符号两种模式**完全相同**（模式只切换「词」，不切换「框」）。

### 16.2 pragma 五条约束

| 约束 | 规则 |
|------|------|
| 不进符号表 | 正式符号仍为 17 对，pragma 不参与容器/配对语义 |
| 不可嵌套 | 不能作为内容被包含，也不能包含内容 |
| 独占一行 | 行内出现其他内容即语法错误 |
| 仅限顶层 | 只能出现在文件顶层，不得位于任何容器/页面/组件体内 |
| 一文件一模式 | 首次 pragma 决定模式；再出现其他模式报错，重复同模式为冗余警告 |

### 16.3 互不互通（v2.4 起）

- 一个构建单元内所有 `.bd` 文件**必须模式一致**。
- **跨模式 `引入` 一律拒绝**，ese check 报错并指明冲突文件。
- 理由：双语本意是「两种母语用户各写各的」，而非维护一套双语文档与混合生态；不互通让文档、报错、测试各自单一语言，同时避免中英组件名混排损害可读性。
- 代价：两个社区不共享组件库，`ese-ui` 需提供两套同构发布。
- 出路：未来提供源到源转换工具 `ese convert --to=ee`，把项目关键字整体翻译到另一模式（标识符不变），作为跨模式唯一官方通道。

## 十七、异步能力预留声明

ese 当前**完全同步**：执行块按源码顺序执行、`跳转` 同步生效、无并发/回调/生命周期。为避免未来发明语法破坏括号体系，v2.4 预先冻结三个语法位（**不实现、当前使用即报错**）：

| 预留语法 | 形式 | 未来含义 |
|----------|------|----------|
| 等待语句 | `等待 3秒` / `wait 3s` | 暂停当前执行块，界面不阻塞 |
| 异步执行块 | `[> 异步 名字 : … >]` / `[> async name : … >]` | 块内可用 `等待` 与网络请求 |
| 生命周期钩子 | `当 组件加载` / `当 组件卸载` | 组件挂载 / 卸载时触发 |

预留语法**不引入任何新括号对**——`等待` 是语句关键字、`异步` 是执行块修饰词、钩子复用执行块结构。符号表仍是 17 对。

## 十八、形式化文法（EBNF）

```ebnf
(* ===== 顶层 ===== *)
program      = pragma? , file-head , { item , LF } , file-tail ;
pragma       = "[" , ("ee" | "zz") , "]" , LF ;
file-head    = "[" , "ese.bd" , LF ;
file-tail    = "]" ;
module-file  = "[" , identifier , ".bd" , LF , { item , LF } , "]" ;

(* ===== 条目 ===== *)
item         = container | comment | divider | pragma | newline-gap ;
newline-gap  = (* 空行，忽略 *) ;

(* ===== 容器类 ===== *)
container    = panel | text | media | input | button | action-button
             | route-page | route | branch | loop | data | calc
             | component-def | component-call | exec ;

panel        = "[" , "+" , attr* , LF , { item , LF } , "]" ;
text         = "[" , "-" , text-body , "-" , "]" ;
media        = "[" , "*" , filename , attr* , "*" , "]" ;
             (* filename 禁含 "*" 与空白（v2.9）；带空白时用引号形式；
                attr* 为 v2.9 新增的可访问性等属性，如 替代="…" *)
input        = "[" , "=" , identifier , "=" , "]" ;
button       = "[" , "c" , "." , SP , [ button-text , SP ] , "." , "c" , "]" , [ jump ] ;
             (* 按钮定界 (v2.8)：定界符 "c." 之后与 ".c" 之前各须至少一个空白；
                紧贴形态（如 [c.a.c]）不是按钮，按列表解析（见 7.5）；
                终止序列为 SP + ".c]"；button-text 不得含 "]"；允许单个半角 ")" *)
button-text  = { any-char - "]" } ;
action-button= "[" , ">" , text-body , "<" , "]" , [ invoke ] ;
invoke       = ("调用" | "call") , exec-name , [ args ] ;   (* v2.9：绑定处可传参 *)
args         = "(" , [ value , { "," , value } ] , ")" ;
route        = "[" , "/" , path , "/" ] ;
jump         = ("跳转" | "goto") , path ;

exec         = "[" , ">" , [ ("异步" | "async") ] ,
               [ exec-name , [ params ] , ":" ] , LF , { item , LF } , "]" ;
               (* v2.9：命名逻辑块可声明形参；无名执行块到达即执行 *)
params       = "(" , identifier , { "," , identifier } , ")" ;

branch       = "[" , "?" , condition , LF , { item , LF } , else-part? , "]" ;
else-part    = "[" , "??" , LF , { item , LF } , "?]" ;
condition    = or-expr ;
or-expr      = and-expr , { ("或者" | "or") , and-expr } ;
and-expr     = cmp-expr , { ("并且" | "and") , cmp-expr } ;
cmp-expr     = arith-expr , [ compare-op , arith-expr ] ;
compare-op   = "==" | "!=" | ">" | "<" | ">=" | "<=" ;
arith-expr   = term , { ("+" | "-") , term } ;
term         = unary , { ("*" | "/") , unary } ;
unary        = [ ("非" | "not") | "-" ] , primary ;
primary      = value | func-call | "(" , or-expr , ")" ;

loop         = "[" , "~" , ( count | iterate ) , LF , { item , LF } , "]" ;
count        = ( number , ("次" | "times") ) | ( identifier , ("次" | "times") ) ;
iterate      = ("遍历" | "for") , identifier , ("为" | "as") , identifier , [ key-attr ] ;
key-attr     = ("键" | "key") , "=" , value ;        (* v2.9：重渲染身份 *)

data         = "[" , "#" , identifier , "=" , value , "#" , "]" ;
calc         = "[" , "$" , [ ("派生" | "derived") ] , identifier , "=" , or-expr , "$" , "]" ;
             (* v2.9：带 派生 修饰者为只读派生值 *)

(* ===== 路由页面 ===== *)
route-page   = "[" , "/" , ("页面" | "page") , path , LF , { item , LF } , "]" ;
path         = path-segment , { "/" , path-segment } ;
path-segment = identifier | "{" , identifier , "}" ;

(* ===== 组件 ===== *)
component-def  = "[" , "+" , ("组件" | "component") , identifier , LF ,
                 { attr-line | item , LF } , "]" ;
attr-line      = ("属性" | "prop") , prop-def , { "," , prop-def } ;
prop-def       = identifier , [ type-name ] , [ "=" , value ] , [ ("必须" | "required") ] ;
               (* v2.9：类型标注 + 必须；两者均可省，省略即 v2.2 的宽容属性 *)
type-name      = "文字" | "数字" | "是否" | "名单" | "字典" | "任意"
               | "text" | "number" | "bool" | "list" | "dict" | "any" ;
component-call = "[" , "<" , qual-name , prop-pass* , ">" , "]" ;
               | "[" , "<" , qual-name , prop-pass* , LF , { item , LF } , ">" , "]" ;
qual-name      = identifier , { "." , identifier } ;   (* v2.9：命名空间引用 *)
prop-pass      = identifier , "=" , ( string | number | identifier ) ;
children-render= ("渲染" | "render") , ("内容" | "children") ;

(* ===== 复用与杂项 ===== *)
import       = ("引入" | "import") , string ,
               ( ("的" | "from") , identifier , { "," , identifier }
               | ("为" | "as") , identifier ) ;
             (* v2.9：第二种形式绑定命名空间，默认命名空间 = 文件名去扩展名 *)
comment      = "[" , "!" , { any-char } , "!" , "]" ;
doc-comment  = "[" , "!" , ("文档" | "doc") , ":" , { any-char } , "!" , "]" ;
             (* v2.9：文档注释，语义同普通注释，仅供 ese doc 消费 *)
divider      = "[" , "-" , "-" , "-" , "]" ;
inline-sep   = "[" , "!" , "!" , "]" ;
assert       = ("断言" | "assert") , string , condition ;
wait-stmt    = ("等待" | "wait") , number , ("秒" | "s") ;   (* 预留，报错 *)

(* ===== 表达式与值 ===== *)
value        = string | number | identifier | member-access | event-object
             | list-literal | dict-literal | boolean | interpolation ;
event-object = ("事件" | "event") , "." , identifier ;   (* 仅执行块内可用（v2.9） *)
interpolation= "{" , member-access , "}" ;       (* 仅 text-body 与 string 内 *)
member-access= identifier , { "." , identifier } ;  (* 点号两侧不得有空白（v2.8） *)
list-literal = "[" , [ value , { "," , value } ] , "]" ;   (* 仅值位置 *)
dict-literal = "{" , dict-pair , { "," , dict-pair } , "}" ;(* 仅值位置 *)
dict-pair    = string , ":" , value ;
boolean      = "是" | "否" | "true" | "false" ;
func-call    = identifier , "(" , [ value , { "," , value } ] , ")" ;
attr         = identifier , "=" , value ;

(* ===== 词法 ===== *)
identifier   = letter , { letter | digit | "_" } ;   (* 中文字符视为 letter *)
string       = '"' , { any-char } , '"' ;
number       = digit , { digit } ;
filename     = { any-char - "*" - SPACE }
             | '"' , { any-char } , '"' ;   (* v2.9：文件名禁含空白；带空白用引号形式 *)
SPACE        = (* 单个空白字符 *) ;
text-body    = { any-char - "-" } | interpolation ;
SP           = (* 至少一个空白字符（半角空格或制表符）。普通词法间隙自动忽略，
                  但 button 产生式中的 SP 是语法成份，不可省（见 7.5） *) ;
```

### 文法要点

1. **`statement = container`**：语句即容器，闭合即结束——「换行即结束」的形式化表达。
2. **预留符号不在文法中**：`[b d] [u n] [q p] [@ @]`、`等待`、`异步` 修饰的开放版本前均不可由文法推导，解析器遇到即报错。
3. **关键字按模式解析**：文法结构不随模式变化，中文/英文字符串在终端层等价替换。
4. **`pragma` 仅在 program 顶层出现一次**，其余位置的 pragma 非法。
5. **插值与字典的双语义**由位置区分：`interpolation` 只出现在 `text-body` 与 `string` 内。
6. **按钮的空格是语法成份**：`button` 产生式里的 `SP` 不可省略。因此 `[c.a.c]` 无法推导为按钮，只能推导为 `list-literal`（元素是点语法 `c.a.c`）——这是按钮与列表之间唯一且完备的分界，也是位置裁决可以降级为纯诊断的原因（v2.8）。
7. **点语法不得含空白**：`member-access` 的点号两侧紧贴，`用户 . 名字` 不可推导（v2.8）。
8. **属性契约完全可选**：`prop-def` 的 `type-name` 与 `必须` 均可省略——省略两者即 v2.2 的宽容属性，**文法层面保证向后兼容**（v2.9）。
9. **`派生` 是 `calc` 的可选修饰词**，不改变产生式结构；「只读」由语义规则（13.4）而非文法保证（v2.9）。
10. **`键=` 是 `iterate` 的可选尾巴**，缺省时退回按序号重渲染（v2.9）。
11. **命名空间引用 `qual-name` 只出现在引用位置**（`component-call` 与模块成员引用），值位置的点仍是 `member-access`，两者不重叠（v2.9）。
12. **`doc-comment` 优先于 `comment` 匹配**：以 `文档:` / `doc:` 开头的注释按文档注释处理，其余为普通注释（v2.9）。

## 二十一、规范治理与冻结流程（v2.9）

ese 的长期风险不是语法，而是**规则漂移**：v2.5 → v2.8 四版内按钮定界符改了四次，每次都要用户手工改代码。本节把治理规则写成规范条文。

### 21.1 三条硬规矩

1. **符号表冻结不可破**：正式符号恒为 17 对。任何新能力只能通过关键字、属性、内置函数或编译目标实现——本版新增的属性契约、容错边界、派生值、事件传参、样式白名单全部遵守此约束。
2. **三个机器可读的单一数据源**：

| 数据源 | 内容 | 消费者 |
|--------|------|--------|
| `keywords.json` | 关键字与中英对照表 | 解析器、ese check、文档、编辑器插件 |
| `diagnostics.json` | 错误码与消息模板 | 解析器、ese check、运行时、ese build |
| `grammar.ebnf` | 形式化文法 | 解析器、插件高亮、文档 |

禁止手写第二份；文档中的文法与关键字表均由它们生成。

3. **破坏性变更必须附带迁移工具**，并在版本记录中显式标注「破坏性」。

### 21.2 变更流程

1. 语义变更先走 **RFC**：仓库 `rfcs/` 目录，提案 → 讨论 → 采纳。
2. 采纳后先在**次版本**发布弃用警告（旧写法仍可用，ese check 提示迁移）；再于下一个次版本实施破坏。
3. 每个版本必须同时交付三件：规范增量文档、完整版合并、迁移工具支持情况。

### 21.3 版本口径

- **规范版本**（2.x）与**实现版本**（CLI 独立版本号）解耦。
- 项目 README 与文档站必须同时标注三项：**规范版本 / 实现版本 / 实现状态**（如「规范 v2.9 · 实现 v0.1（仅前端层）」），避免把「设计完成」误读为「可用」。
