## 一、属性契约

### 1.1 类型标注

```
[+ 组件 欢迎卡
  属性 名字 文字 = "游客"
  属性 等级 数字 = 1
  属性 标签 名单
  属性 必填 是否 = 否
  [+ 居中
    [- 你好，{名字}！等级 {等级} -]
  +]
+]
```

类型关键字（中 / 英）：

| 类型 | 英文 | 说明 |
|------|------|------|
| 文字 | text | 字符串 |
| 数字 | number | 整数或小数 |
| 是否 | bool | `是` / `否` |
| 名单 | list | 列表 |
| 字典 | dict | 字典 |
| 任意 | any | 不校验（**未写类型时的默认值，保持 v2.2 兼容**） |

### 1.2 `必须` 修饰

```
[+ 组件 分页
  属性 当前页 数字 必须
  属性 每页条数 数字 = 20
  属性 标题 文字
+]
```

- 带 `必须`（required）的属性在调用处**未传即运行时报错**（严格级，见第八节错误码）。
- 不带 `必须`、也不给默认值：仍沿用 v2.2 的**宽容兜底**（文字取空串、数字取 0），ese check 给警告。

### 1.3 调用处的静态校验

| 情形 | 级别 |
|------|------|
| 缺少 `必须` 属性 | 错误 |
| 传值类型与标注不符 | 错误 |
| 传入组件未声明的属性名 | 警告（拼写保护） |
| 缺少非必须属性 | 警告（宽容兜底生效） |

### 1.4 与 v2.2 的关系

默认仍为宽容——低代码用户需要「页面先能出来」。`必须` 是**显式收紧开关**，按属性逐项打开，**不提供全局严格模式**。

## 二、错误边界与安全取值

### 2.1 安全取值函数

| 中文 | 英文 | 签名 | 行为 |
|------|------|------|------|
| 取 | get | `取(字典, 键, 缺省)` | 键不存在返回缺省，**不终止** |
| 取或 | getOr | `取或(列表, 序号, 缺省)` | 越界返回缺省，**不终止** |

`取第` 保持严格（越界即停）——**严格是默认，安全取值是显式选择**，与属性契约同一套哲学。

```
[$ 名字 = 取(用户, "名字", "游客") $]
[$ 第一 = 取或(名单, 1, "") $]
```

### 2.2 容错容器

```
[+ 容错 兜底="数据加载失败"
  [- 总价：{单价 * 数量} -]
+]

[< 图表 数据=报表 容错=是 兜底="图表暂不可用" >]
```

规则：

1. `容错`（tolerant）是**开关属性**，可出现在任意容器与组件调用上；`兜底`（fallback）指定降级显示的文字。
2. 其内部发生的**严格级错误被捕获**：该容器整体渲染为 `兜底` 文字（未给 `兜底` 时为空）。
3. 错误**不静默**：仍写入控制台与 `ese serve` 日志，并带完整错误码。
4. 未使用 `容错` 时行为完全不变——**立即终止**。
5. **错误不穿透组件边界**：组件内部错误由组件自己的 `容错` 负责，调用方不接管（避免责任不清）。

**设计理由**：低代码场景下，一个字段缺失导致整页白屏的代价过高；`容错` 把「降级范围」交给用户**显式声明**，粒度可细到单个组件，且**不引入 try/catch 语法**，符号表不受影响。

## 三、列表键（重渲染身份）

```
[~ 遍历 购物车 为 项 键={项.id}
  [- {项.名字} -]
  [= 数量 =]
~]
```

- `键`（key）只能是**值位置表达式**，同一循环内必须唯一。
- 有键时，重渲染按身份复用节点：输入框焦点、动画状态、滚动位置得以保持。
- 无键时行为同 v2.8（按序号重渲染）；ese check 检测到「循环内含输入框或组件却无键」时给出警告「可能丢失输入焦点」。

## 四、派生值

```
[# 单价 = 12 #]
[# 数量 = 3 #]
[$ 派生 总价 = 单价 * 数量 $]
```

规则：

1. 派生值**只读**——对其赋值是错误（ESE2007）。
2. 依赖自动追踪：任一所依赖状态被赋值时自动重算，界面同步更新。
3. 派生值不引入新的状态层级，仍属于声明所在层（全局 / 页面 / 组件）。
4. 允许链式派生；**循环依赖**在 ese check 阶段报错（ESE2008）。

## 五、事件传参与事件对象

```
[> 加购(编号) :
  [$ 购物车 = 加入(购物车, 编号) $]
>]

[~ 遍历 商品 为 项
  [> 加购 <] 调用 加购({项.id})
~]
```

- 命名逻辑块可声明形参：`[> 名字(参数1, 参数2) : … >]`
- 绑定处传参：`调用 名字(实参, …)`；无参仍写作 `调用 名字`。
- 执行块内可用**事件对象** `事件`（event）：

| 字段 | 含义 |
|------|------|
| `事件.值` | 触发元素的值（输入框内容） |
| `事件.索引` | 列表项序号（从 1 起） |
| `事件.项` | 列表项本身 |
| `事件.目标` | 触发组件 / 元素的名字 |

约束：参数按值传递（不传引用）；实参与形参数量不符为错误（ESE2009）；形参重名为错误。

## 六、样式逃生舱

```
[+ 类="卡片主" 样式="圆角:12; 字号:15; 色:#333333"
  [- 正文 -]
+]
```

**白名单（12 项，v2.9 定稿）**：色、背景、边框、圆角、字号、字重、行高、间距、内距、外距、对齐、宽度。

- 白名单**之外**的属性一律拒绝并报错（ESE2010）——防止 ese 退化成 CSS 宿主。
- `类`（class）指向项目 `样式.fmt` 中定义的类，或 ese-ui 内置类。
- 优先级：`样式` > `类` > 内置默认。

**设计理由**：没有逃生舱就做不出真实设计；无限逃生舱则语言失去形状。白名单是二者唯一的可行折中。

## 七、可访问性

```
[* 头像.png 替代="张三的头像" *]
[= 名字 标签="用户名" 提示="请输入姓名" =]
```

| 元素 | 新增属性 | 编译为 |
|------|----------|--------|
| 媒体块 | `替代` / alt | `<img alt="…">` |
| 输入框 | `标签` / label | `<label>` 与 `for` 关联 |
| 输入框 | `提示` / placeholder | `placeholder` |

- ese check 对**缺 `替代` 的媒体块**给警告。
- **词法收紧（v2.9 起，破坏性）**：媒体块的文件名定义为「首个空白前、且不含 `*` 的片段」。因此 `[* 带空格 的名字.png *]` 非法，须写 `改名` 或使用引号形式 `[* "带空格 的名字.png" 替代="…" *]`。

## 八、诊断规范与错误码

### 8.1 错误码分段

| 段 | 范围 | 示例 |
|----|------|------|
| `ESE1xxx` | 词法与语法：括号配对、预留符号、按钮定界、模式冲突 | ESE1001 括号未闭合 |
| `ESE2xxx` | 静态检查：类型、作用域、属性拼写、派生循环 | ESE2003 未知属性 |
| `ESE3001`–`ESE3xxx` | 运行时：除零、越界、类型不匹配 | ESE3001 除以零 |
| `ESE4xxx` | 构建与工具：清单不一致、模式冲突、迁移失败 | ESE4001 模式冲突 |

### 8.2 诊断对象（工具链统一结构）

```json
{
  "code": "ESE3001",
  "severity": "error",
  "file": "ese.bd",
  "line": 12,
  "column": 5,
  "message": "除以零",
  "hint": "检查除数，或使用 容错 降级显示"
}
```

### 8.3 文本格式

```
错误 ESE3001 ese.bd:12:5 除以零（[$ 一半 = 总数 / 0 $]）
提示 检查除数，或使用 容错 降级显示
```

- 报错语言**跟随文件模式**（`[zz]` 中文 / `[ee]` 英文），不由用户配置。
- 消息模板由 `diagnostics.json` **单一数据源**生成，禁止手写第二份。

## 九、模块命名空间与项目清单

### 9.1 命名空间引用

```
引入 "./ui.bd" 为 ui
引入 "./工具.bd" 的 格式化, 校验

[< ui.卡片 标题="公告" > [- 正文 -] >]
```

- `引入 … 为 名字` 绑定命名空间；不写 `为` 时默认命名空间 = 文件名去扩展名。
- 引用名为 `命名空间.组件名`。点号**仅在被引用位置解析**，与值位置的点语法（§6.2）不冲突。
- 跨模式引入仍然一律拒绝（见 v2.4 不互通规则）。

### 9.2 项目清单 `ese.json`

```json
{
  "名称": "我的站点",
  "模式": "zz",
  "入口": "ese.bd",
  "ui": "1.0"
}
```

- 声明构建单元的根与模式；`ese build` / `ese check` / `ese test` 由它确定工作范围。
- 清单 `模式` 与文件内 pragma 不一致 → ESE4001。
- 兼容：无 `ese.json` 时按「目录内唯一 `ese.bd`」推断。

## 十、文档注释与 `ese doc`

```
[! 文档 : 带标题的卡片容器，正文由调用处提供。属性 标题 为卡片抬头文字。 !]
[+ 组件 卡片主
  属性 标题 文字 = ""
+]
```

- 以 `文档`（doc）开头的注释为**文档注释**，绑定其后紧邻的定义（组件、函数）。
- `ese doc` 扫描全部文档注释与属性契约，生成 Markdown / HTML 版 API 文档。
- **不新增括号对**——复用 `[! !]` 注释。

## 十一、迁移工具与冻结治理

### 11.1 自动迁移 `ese fmt --migrate`

| 旧形态 | 新形态 |
|--------|--------|
| `[( 文字 )]`（v2.5） | `[c. 文字 .c]` |
| `[(( 文字 ))]`（v2.6） | `[c. 文字 .c]` |
| `[c.文字.c]`（v2.7 紧贴写法） | `[c. 文字 .c]` |

按钮定界符在三版内改了三次，**不能让用户手工改**。该工具的实现优先级**高于解释器**，与 ese check 同期交付。

### 11.2 冻结与变更流程

1. **符号表冻结不可破**：17 对上限恒定，能力扩展只能走关键字 / 属性 / 内置函数 / 编译目标。
2. **三个机器可读单一数据源**：`keywords.json`（关键字与中英对照）、`diagnostics.json`（错误码与消息模板）、`grammar.ebnf`（文法）。解析器、ese check、文档、编辑器插件**全部由它们生成**。
3. **语义变更走 RFC**：仓库 `rfcs/` 目录，提案 → 讨论 → 采纳。采纳后先发**弃用警告**，再于下一个次版本破坏。
4. **破坏性变更必须附带迁移工具**，并在版本记录中显式标注「破坏性」。
5. **规范版本与实现版本解耦**：规范 2.x，CLI 独立版本号；README 须标注「规范版本 / 实现版本 / 实现状态」。

### 11.3 实现期 P0 清单（更新）

1. `keywords.json` + `diagnostics.json` 落地（两个文件、四个消费者）。
2. 属性契约静态校验（类型 + `必须` + 拼写警告）。
3. 容错边界的捕获范围与组件边界策略（**建议：不穿透**）。
4. 派生值的依赖图与循环检测。
5. 遍历键与 SSR 水合的一致策略。
6. 样式白名单 12 项的最终定稿。
7. `ese fmt --migrate` 先于解释器。
8. 全部错误消息模板的中英双份（由 `diagnostics.json` 生成）。

## 十二、明确拒绝或推迟的建议

| 建议 | 处置 | 理由 |
|------|------|------|
| 完整类型系统（结构体 / 泛型 / 接口） | 推迟 v3.0 | 与「中文低门槛、低代码」定位冲突；契约层已覆盖 90% 误用场景 |
| `try/catch` 式捕获语法 | **永久拒绝** | 违反符号冻结与极简定位；由 `容错` + 安全取值函数覆盖 |
| 全局严格模式开关 | 拒绝 | 改为 `必须` 逐项收紧，避免一刀切吓退低代码用户 |
| 完整 CSS 支持 | 拒绝 | 改为 12 项白名单，保住语言形状 |
| 新增括号对表达任何能力 | **永久拒绝** | 见设计哲学第 6 条（符号冻结） |
