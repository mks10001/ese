```bash

```

它**不是**解释器——`ese fmt` 只做缩进与历史语法迁移，`ese spec verify` 只校验元数据。区别很重要。

## 这是什么

ese 是一个**面向中文用户的网页构建语言**。它的目标不是取代 JavaScript，而是让「第一次做网站的人」能写出一个真实可用的页面——包括数据、判断、循环、组件与多页面。

三条不可动摇的设计约束：

1. **对称即语法**：每个符号都是一对括号，左右呼应。看见开头就知道结尾，配对错误肉眼可查。
2. **符号冻结**：正式符号恒定为 **17 对**。任何新能力只能通过关键字、属性、内置函数与编译目标实现。规范从 v2.0 到 v2.10 新增了字面量、路由、状态、组件、测试、SSR、双语、契约层、错误边界、诊断体系、迁移工具——**一对括号都没加**。
3. **中文优先，双语对等**：默认中文关键字，`[ee]` 英文模式完全对等；两种模式**互不互通**（一个构建单元内语言统一，避免中英混排）。

## 一段代码

```
[zz]
[ese.bd
  [+ 组件 计数器
    属性 起始 数字 = 0
    [# 当前 = 起始 #]
    [$ 派生 双倍 = 当前 * 2 $]
    [+ 居中
      [- 当前计数：{当前}（双倍：{双倍}） -]
      [> 加一 <] 调用 加一
    +]
    [> 加一 :
      [$ 当前 = 当前 + 1 $]
    >]
  +]

  [/ 页面 home
    [- 欢迎回来 -]
    [< 计数器 起始=10 >]

    [# 待办 = ["买菜", "写代码"] #]
    [~ 遍历 待办 为 项 键={项}
      [- {项} -]
    ~]

    [c. 去关于页 .c] 跳转 about
  /]
]
```

同一段逻辑的英文模式（同一个项目内不得混用两种模式）：

```
[ee]
[ese.bd
  [+ component Counter
    prop start number = 0
    [# current = start #]
    [$ derived double = current * 2 $]
    [+ center
      [- count: {current} (double: {double}) -]
      [> add <] call add
    +]
    [> add :
      [$ current = current + 1 $]
    >]
  +]
  [/ page home
    [- Welcome back -]
    [< Counter start=10 >]
    [c. to about .c] goto about
  /]
]
```

## 符号总表（17 对，冻结）

| 符号 | 名称 | 用途 |
|------|------|------|
| `[+ +]` | 浮雕框 | 页面容器，支持属性（宽 / 居中 / 背景 / 样式 / 容错…） |
| `[- -]` | 文字块 | 显示文字，支持 `{变量}` 插值 |
| `[* *]` | 媒体块 | 图片或视频，支持 `替代="…"` |
| `[= =]` | 输入框 | 绑定变量，支持 `标签` / `提示` |
| `[c. .c]` | 按钮 | 纯按钮（配合 `跳转`）；**`c.` 后与 `.c` 前各须一个空格** |
| `[> <]` | 行为按钮 | 点击触发命名逻辑块，可传参 |
| `[/ /]` | 路由 | 页面路径声明 / 跳转目标 |
| `[---]` | 分割线 | 横线 |
| `[> >]` | 执行块 | 定义命名逻辑块（可带形参）/ 立即执行 |
| `[? ?]` | 分支块 | 条件判断 |
| `[?? ??]` | 否则分支 | 只能在 `[? ?]` 末尾 |
| `[~ ~]` | 循环块 | 计数循环 / 遍历循环（支持 `键=`） |
| `[# #]` | 数据抽屉 | 声明变量 |
| `[$ $]` | 计算器 | 赋值、运算、`派生` 值 |
| `[< >]` | 组件调用 | 调用组件，可携带子内容 |
| `[! !]` | 注释 | `[! 文档 : … !]` 形式可生成 API 文档 |
| `[!!]` | 行内分隔符 | 可选，仅一行写多条语句时使用 |

与符号同样重要的是**刻意不提供**的东西：没有 `try/catch`（改用 `容错` 容器 + 安全取值 `取`）、没有任意 CSS（12 项白名单）、没有完整类型系统（契约层只做类型标注与 `必须`）。每一次「不做」都在规范里写明了理由。

## 快速开始

### 工具链：现在就能跑

不需要 `npm install`，不需要构建。Node ≥ 22.18 内置 TypeScript 类型擦除，直接运行源码：

```bash
node tools/src/cli.ts spec verify                  # 校验三个单一数据源的一致性
node tools/src/cli.ts fmt --rules                  # 查看全部六条迁移规则
node tools/src/cli.ts fmt --migrate .              # dry-run：打印差异，不改盘
node tools/src/cli.ts fmt --migrate --write .      # 确认无误后落盘
node tools/test/run.ts                             # 46 项自测
```

`ese fmt` **默认 dry-run**。这是刻意的：在 `ese check` 可用之前改写没有二次校验，静默破坏用户代码的风险高于多敲一个 `--write`。

### 语言：还不能运行

```bash
ese check          # ⏳ 静态检查：括号配对、属性契约、诊断码
ese build          # ⏳ 静态生成：页面预渲染为 HTML
ese serve          # ⏳ 服务端渲染 + 水合
ese test           # ⏳ 运行 *.test.bd，双语项目执行双模式回归
ese doc            # ⏳ 生成组件 API 文档
```

**以上五条尚未实现，勿据此使用。** 仓库里现在只有规范、元数据与静态处理工具。

## 参与贡献

**在提任何语言层面的建议之前，请先读这一节。**

1. **符号表不讨论**。17 对是硬约束，不接受「再加一个括号」类提案——这类 Issue 会被直接关闭并附本节链接。
2. **语义变更走 RFC**：在 `rfcs/` 提目录（编号 + 提案文档），说明动机、语法、对现有代码的影响、是否有破坏性与迁移方案。
3. **破坏性变更必须附迁移工具**，否则不予受理。
4. **双语约定**：文档与报错消息**不得**手工维护中英两份。关键字与消息模板由 `keywords.json` / `diagnostics.json` 生成；直接改生成产物会被拒绝。`ese spec verify` 会拦住不一致的 PR。
5. **实现优先于规范**：当前仓库最缺的是代码。`ese check`、VSCode 插件、解释器的 PR 欢迎度高于任何规范润色。
6. **改文法要双向同步**：改 `spec/grammar.ebnf` 必须同时改规范 §18，反之亦然；PR 需附 `ese spec verify` 通过截图。
7. **迁移工具不得猜测**：改写类规则在判据不足时必须报错拒绝（`ESE4004`），不得「按最可能的意图」替换。静默改义是本项目最不可接受的缺陷类型。

## 治理与版本口径

- **规范版本**（`2.x`）与**实现版本**（CLI 独立版本号）解耦。
- 每个 Release 同时标注三项：**规范版本 / 实现版本 / 语言可执行性**。
- Tag 规则：规范用 `spec-v2.10`，实现用 `cli-v0.1.0`。
- 语义变更流程：RFC 采纳 → 次版本发**弃用警告** → 下一个次版本破坏。详见规范第二十一节。

## 常见问题

**为什么不用 HTML / JSX？**
ese 不与它们竞争表达能力——正面比较一定会输。ese 的位置是「**中文可视化网页构建语言**」：面向第一次做网站的中文用户、面向教学场景（积木编程 → 真实网页的过渡）、以及可 Git 管理的开源低代码格式。

**为什么两种模式互不互通？**
双语的本意是「两种母语用户各写各的」，不是维护一套双语混合生态。不互通让文档、报错、测试各自只有一种语言。代价是两个社区不共享组件库，`ese-ui` 需双套同构发布；未来以 `ese convert` 源到源转换作为唯一官方跨模式通道。

**为什么按钮要写成 `[c. 文字 .c]`，还要空格？**
因为它是唯一能同时在词法层面与列表 `[...]`、括号表达式 `(...)`、点语法 `a.b` 都不同源的写法。定界符内侧的空格**是语法成份**，不是排版习惯。历史上这个符号改过四次（v2.5 → v2.8），每一次的原因都记在版本记录里——这是本语言最深的一课。

**17 对符号真的够吗？**
v2.0 → v2.9 共新增字面量、点语法、遍历、路由、三级状态、组件与插槽、测试、SSR、双语、属性契约、错误边界、派生值、事件传参、诊断体系、样式白名单、可访问性——一对括号都没加。够不够由后续实现检验，但至少证明了「不靠加符号也能长大」。
