# spec/ —— 机器可读的单一数据源

本目录存放 ese 语言的**机器可读定义**。它与 `docs/ese语言规范-完整版.md`（人读规范）是同一份语义的两种呈现：

> **规范文档是给人读的，`spec/` 是给工具读的。两者不一致时，以 `spec/` 为准并开 Issue 修正文档。**

之所以必须存在这一层，是因为 ese 有一个硬性约束：**关键字与报错消息不得手工维护中英两份**（见规范第十六节、第二十一节）。`keywords.json` 与 `diagnostics.json` 是这条约束的唯一执行手段——VSCode 插件、`ese check`、运行时、文档生成器全部从这两个文件读取，禁止各自硬编码。

## 计划中的三个文件

### `grammar.ebnf`

从规范第十八节提取的完整 EBNF 文法。是 `ese check` 解析器的权威依据。

- 覆盖全部 17 对正式符号，**不含预留区**（`[b d]` `[u n]` `[w m]` `[q p]` `[@ @]` 解析即报错）
- 含表达式优先级层级：`or-expr → and-expr → cmp-expr → arith-expr → term → unary → primary`
- 含 `SP` 终结符（按钮定界符内侧的空格是语法成份，非排版习惯）

### `keywords.json`

中英关键字对照表，18 组（组件 / component、属性 / prop、调用 / call、遍历 / for、跳转 / goto……）。

设计要求：

- 每个关键字一条记录，包含中文形、英文形、所属语法位置
- 中英两形**必须同批增删**，不允许单侧存在
- 工具链（高亮、补全、诊断消息）只读此文件

### `diagnostics.json`

全部诊断码与消息模板。

- 码段：`ESE1xxx` 词法 / `ESE2xxx` 语法 / `ESE3xxx` 语义 / `ESE4xxx` 工程与配置
- 每条含：错误码、严重级别（错误 / 警告）、中英双份消息模板、占位符列表、触发条件说明
- 消息模板内的变量用占位符表示（文件名、行号、符号名、原因），由工具填充

## 当前状态

**三个文件均未生成。** 它们列在 README 路线图的第 ② 步，排在 `ese fmt --migrate` 之后。在生成之前：

- 本目录不对工具链提供任何输入
- 任何工具的实现必须等待本目录就绪，**不得先行硬编码关键字与消息**

## 一致性校验（CI 目标）

三个文件就绪后，CI 需校验：

1. `grammar.ebnf` 中出现的关键字，全部存在于 `keywords.json`
2. `keywords.json` 中的中英两形数量相等，且无重复
3. `diagnostics.json` 中的错误码中英消息模板占位符集合一致
4. 符号对总数恒为 17，且与规范第三节符号总表一致
